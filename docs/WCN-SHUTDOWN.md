# 蓝牙停止与自动回程 · 2026-11-12

后续整核闭环已完成，见[profiles/v97-wcn](../profiles/v97-wcn/README.md)：19个蓝牙对象和2个
既有对象已编译、链接/prelink，实际启动/停止分支、共享owner和五固件唯一副本均通过独立静态核验。
30个原始Apple执行区未变。未做entry转换或boot签包，也未上机；下文的“整核待办”保留为前一阶段记录。

现有WCN电源、UART、五固件/HCI和NativeHost代码已经接起主要调用链，但常驻mode4
没有接入RPC关机流程。它只在桥接故障时退出；上行缓冲满时还可能停止读取UART，
单靠撤销电源许可无法让该循环退出。这是以后无人值守启用蓝牙前需要补齐的缺口。

本次源代码补齐停止生命周期：

1. RunControl将未启动、排队、运行、停止中、已停和未知占用分开。停止后不能排队重启；
   worker创建失败或排队取消不会遗留“正在运行”。
2. 停止请求关闭后续UART acquire/live许可，正在执行的有界事务由原线程收尾；
   已验证radio-stopped的释放许可仍保留。请求方不并发写BT_EN或共享电源。
3. NativeHost在每轮直接检查停止请求，缓冲满也能退出；撤回服务、属性和准确进程引用的原路径保留。
4. 原WCN worker再执行BT_EN低、等待/回读、UART关闭和电源账本收尾。
   失败/未知事务保持Held；共享boot消费者的基础rail票不降低或清除。
5. 通用SDAM恢复模板通过弱接口调用该流程，最多900次10ms等待；超时或Held明确报告未确认，
   之后继续既有平台回程。WCN未编入时没有此调用。panic中不新增PMIC操作。

没有改变PMIC/GPIO值、rail电压、协议数据或声学增益；没有开启射频。停止时在途事务可能完成，
这里不承诺中断一半UART数据包。单次候选成功也不能证明休眠或所有共享消费者的电源管理正确。

## 已验证与未验证

[机器可读证据](evidence/wcn-shutdown-20261112.json)绑定当前源码和结果。
主机ASan/UBSan通过17个UART平台场景和12个桥接场景，新增覆盖停止后零新UART事务、
复位前拒绝释放、复位后归还且保留其他GCC消费者，以及上行背压时停止/拒绝新连接。
旧五固件完整路径和截短HCI应答检查也保留。大量字节比较断言不当作额外硬件工况。

WcnPowerNative与NativeHost用已核XNU C++上下文编译为ARM64/iOS17对象，导出接口保留、
新stop调用与定义相符，机器码没有FP/SIMD。内核控制接口缺少的头文件取自同一重建XNU，
逐文件记录SHA，编译器的封闭源码覆盖层保持，不用临时伪造声明填洞。

**尚未重链完整内核、未构建新boot、未验射频或实际关机。** 通用恢复模板已接接口，
但冻结v91/v94恢复源码没有修改；下一蓝牙profile须显式携带此补丁并完成完整ABI/原始执行区/
