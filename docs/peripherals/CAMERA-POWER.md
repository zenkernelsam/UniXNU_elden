The front/rear sensor path now uses a source-derived WL2868C supply controller
through the one existing backlight I2C10/GENI engine. The original sensor/CCI/
CSIPHY/CSID/VFE capture code calls that controller through `PowerBinding.h`.
The complete offline OS17 image links and its existing peripheral/recovery
audits pass. No camera power owner is installed automatically, no tablet was
accessed, and neither real pixels nor the iPadOS camera service is accepted.

## Shared owner and cleanup

`SharedBusSource.py` derives an overlay of the pinned original backlight
sources, including the already qualified boot alias/PD observation variant.
One sleepable serial mutex covers **all** brightness, health, diagnostic and
camera transactions. The same `Context`, mappings and GENI engine service both
chip addresses. Legacy0x76 register permissions stay unchanged;0x2f access is
restricted to ID0, selectors3..9 and enable0x0e. Successful transactions restore
the engine's software address to0x76 after actual hardware-idle proof.

Published Context/port/mutex storage stays retained to reset. The camera borrows
once with an explicit owner/epoch and original physical authority. Shared open
checks that authority both before and under the mutex. Interrupt-context calls,
stale identity, closed admission and already-owned/faulted engines refuse.
There is no second MMIO controller, raw user IOCTL, hidden firmware or new
independent clock setup.

`Power.c` records **attempted** supply references before writes, separately from
fully observed active users. It checks ID, actual enable and held voltage on
normal calls; enabled mismatching voltage or unowned changed selectors refuse.
It preserves originally enabled channels and their selectors. The original
regulator owner must provide `rail_unused(ldo1..7)` before any voltage mutation
or last owned disable: two sensor counters cannot retire the lens's LDO7 use.

Last sensor withdrawal requires real sensor/CSI/DMA inactivity. An ambiguous
enable/disable/readback error retains its ledger; a later cleanup samples actual
hardware, disables only its own bit and restores only its recorded selector.
It never changes a live rail's voltage. Missing/foreign ownership retains all
resources. Final stop requires no references, both cameras inactive and actual
restoration. SYS is cleared only when this owner added it and no channels are
live; if another channel needs SYS, that dependency is recorded and preserved.

`PowerBus.c` binds the actual session to the shared engine and makes close prove
the WL ledger is stopped/restored plus both cameras are physically inactive.
Closing public admission does not remove cleanup authority. If backlight has
already completed timer/tick/original-brightness restoration, it defers bus
release while camera holds a borrow. Camera retirement then finishes that real
release once; failed abort/idle/clock restoration retains maps/lease to reset.
No uncertain engine is reopened.

`PowerBinding.c` connects this supply session to the existing explicit capture
wrappers. Real reset, MCLK, board admission and timing remain mandatory external
callbacks; the board callback cannot substitute a fake rail result. Stop the
sensor and physically drain its receiver before withdrawing its last supply,
then stop CCI; stop both captures before `power_session_stop`. Mainline must
integrate this with its current original camera/backlight recovery order. The
offline image's established recovery object and deadlines are unchanged.
