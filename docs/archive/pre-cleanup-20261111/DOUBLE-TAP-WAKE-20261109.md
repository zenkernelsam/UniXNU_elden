# Y700 双击熄屏唤醒：正式需求

2026-11-09，用户确认原厂 Android 已开启并在使用“双击熄屏亮屏”，要求移植到 iPadOS。
这是本机明确需要的功能，不以某款 iPad 是否支持相同手势作为前提。
此前恢复 Android 后的亮屏与用户正在操作平板重叠；不能把相应 WAKE_REASON_WAKE_KEY 日志判为异常唤醒。

## 目标与接入

- 可开启/关闭双击唤醒；开启时熄屏后双击屏幕唤醒至锁屏，之后按既有认证规则解锁。
- 亮屏、上滑解锁、Face ID 是不同功能；双击亮屏不会跳过密码认证，也不提供 Face ID 硬件。
- 随触控 M1 与电源/睡眠 M8 协作实现：确认 NT36536 原厂手势识别及低功耗模式、
  TLMM162 的唤醒中断路由，再接 iPadOS 显示/背光恢复和系统唤醒事件。
- 先验“仅显示熄屏→唤醒”，再验整机低功耗睡眠；前者通过不能代替后者。
- 优先复用触控芯片固件的低功耗手势识别。若硬件路径尚不具备，明确记录限制；
  不把常驻 CPU 轮询并保持全功耗触控当作日用完成。
- 与自动息屏、电源键、充电、横竖屏和 USB 日志/恢复路径配合；设置持久化依赖正式 Data 能力，
  RAM Data 中的一次开关不能宣称重启后设置已保留。

## 已查来源与待查事项

用户原厂实用反馈确认本机存在该功能。当前选用的 Armada 指定内核
`h0cheung/tb322fc-linux-kernel@bf96c3d4048973298ede78487177c6f1b4f6bc0f` 中，
`drivers/input/touchscreen/novatek-nvt36xxx-spi.c` 是基础 SPI/固件/点帧驱动，
本次文本核对没有找到 gesture/wakeup/suspend/resume 实现；不能把它当作现成双击唤醒配方。
源码副本和 SHA 在 `research/double-tap-wake-20261109/`，未改变参考仓或设备。

后续需核对本机原厂 Novatek 驱动的手势命令、事件格式、模式退出及电源保持顺序，
再借鉴 sheng 已实机成功的 IOKit/显示恢复方法。本机手势 ID、命令值、IRQ 和电源寄存器
必须来自 Y700 证据，不能从其他 Novatek 型号照抄。
当前自有 `EldenNvt36536` 实现尚未接手势低功耗模式，本需求是待实现项。

## 验收

1. 开关关闭时双击不亮屏；开启后重复双击能到锁屏，单击及普通移动不误触发。
2. 灭屏/唤醒至少连续30轮，触控、背光、旋转和 USB 回程正常，唤醒手势不泄漏为界面误点击。
3. 分别记录仅显示熄屏与系统睡眠时的唤醒延迟、电池电流、误唤醒及漏唤醒。
4. 检查充电/断电、横竖屏、多指、触控复位和中断异常下的行为；待实机条件允许时检查口袋/覆盖误触。
5. 正式 Data 就绪后验证设置重启保留；密码锁屏仍要求正常认证。

本轮仅离线来源核对和计划记录，没有改变 Android 的用户设置或触控硬件。
