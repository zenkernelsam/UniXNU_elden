# Elden GPU board adaptation — in progress

The shared A830 C++ core and Metal/Rust/Turnip artifacts are built separately.
This directory owns the Y700-specific adapter; it is not yet a complete runnable
driver and is not wired into a boot profile.

`EldenGpuVotes.c` adapts the `PaganiGpuVotes.c` flow at device commit `a84204ec`,
but consumes the actual TB322FC/Linux6f97250e tables generated by
`tools/derive_gpu_opp_inputs.py`:14 GPU OPPs,3 GMU OPPs and fuse values
`be/dd/e8/f2` mapped to bins0..3. The higher OnePlus1150/1200MHz rows and its
fuse252 fallback are not imported. Unknown fuses or unavailable requested
frequencies are refused. Off entries are inserted explicitly; the runtime must
supply an exact desired OPP rather than inherit an undocumented policy.

The startup message uses the current live command-db snapshot and existing
Gen8 HFI vote encoders. It keeps output unchanged on any error. IFPC/ACD stay
off until their separate resource prerequisites are implemented. Fifty actual
function tests cover the common OPPs across four bins, selected HFI payloads,
optional rails and transactional failures. These are synthetic rail inputs;
they neither program a regulator nor prove live voltage or frequency behavior.

Public SM8750 firmware is fixed in `config/gpu-firmware.lock.json`. Its GMU
matches the published OnePlus input; SQE, AQE and ZAP differ and are never claimed
stock-identical. `prepare_gpu_firmware.py` validates raw hashes and reuses the
exact reviewed ZAP parser, checks the8KiB Y700 reservation, and emits local-only
firmware assembly plus redistribution notices. Actual PAS authentication and
execution remain a future device observation.

## Remaining native integration

Use the published `package/PaganiGpu.cpp` only as a source reference. Replace its
board inputs and status hooks; do not copy the PKX110 policy wholesale.

- Bind the pinned GPU/GMU/GPUCC/SMMU/cmd-db/SMEM/ZAP resources and verify the
  runtime SoC and mappings before mutation.
- Use the existing shared `Sm8750RpmhWriteActive` provider/DRV2 owner, not an
  independent conflicting request-list writer. WCN's VRM rails and GPU ARC/BCM
  votes are different resources but still share the submission controller.
- Resolve retention of inherited/shared CX/MX votes explicitly; document fixed
  bring-up policy separately from future dynamic power management.
- Integrate the generated OPP/HFI and firmware inputs, real SMMU/GMU/CP/fence
  operations and the A830 six-buffer context; do not enable A740 preemption.
- Replace the four SM8550-bound modules excluded by `build_gpu_native.py` with
  an actual Elden startup and recovery owner. Keep all uncertain GPU/DMA
  allocations retained until a verified reset; do not return success for a
  stubbed stop or firmware operation.
- Connect the GPU publication and existing GOP handoff ABI to the current
  framebuffer, then verify complete native link/initializer/ABI ownership.

The complete offline goal remains active until this integration and a fresh
consolidated end-to-end build pass. The vote component does not close that goal.
